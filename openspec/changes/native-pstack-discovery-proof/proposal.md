# Bounded native PStack discovery proof

## Why

Installation and registration do not establish loaded resource origins or child execution. A separately authorized hosted probe records those facts without activating a new catalog or certifying native readiness.

## What changes

- Reuse the registered test workflow with no new inputs. Only a manual run in tommy-ca/LazyPi on feat/strict-native-pstack-proof selects the native job instead of the ordinary test job.
- Add a private-state outer driver, a public-SDK controller, and a probe-owned deterministic loopback provider.
- Reject missing canonical origin, schema, or effective model-policy proof before any child. Permit at most one unchanged how-explorer foreground delegation.
- Require correlated native read-tool evidence, the private canary, settlement, package terminal status, and actual controller exit.
- Add offline fixture checks and document the proof limits.
- Bind the complete global graph to verified private-cache archive bytes and SRI before discovery, without refetching missing evidence.
- Preserve owned process-group cleanup after leader exit, match pinned foreground index-0 artifacts, reject unknown internal CLI arguments, and disable both native agent and HTTP retries.
- Retain the source-established preflight host_required negative: the parent's session directory is not evidence of the host's child-session-root policy.

## Impact

No installer, catalog, dependency, canonical role, sandbox setting, production provider, or release change. Normal PR, push, and other manual workflow behavior remains intact. Offline fixtures are not native proof. Dispatch, independent acceptance, and reviewed-commit binding remain parent-owned.
