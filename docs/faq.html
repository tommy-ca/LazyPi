Got questions?

FAQ

Pi is powerful. But like Neovim, Arch Linux, or tmux — its minimalism is also its barrier. Out of the box, there's not much to see. The magic lives in the ecosystem: the harness core: sub-agents, the ask gate, skill visibility, goal, web research, FFF search the community has built around it. LazyPi is to Pi what LazyVim is to Neovim, or Omarchy is to Arch — a curated starting point that gets you to an exciting, useful experience immediately, without the research and configuration tax.
What is Pi?
Pi is a minimal AI coding agent built by Earendil & Mario Zechner. It's designed to be small, fast, and focused — a clean foundation you can build on. That minimalism is intentional, but it does mean Pi ships with very little out of the box.
Do I need to install Pi first?
No. If Pi isn't installed on your machine, LazyPi will install it for you as part of the setup. Just run npx @tommy-ca/lazypi and it handles everything.
What does LazyPi install?
LazyPi installs the 12-package harness core by default. The 5-package optional tier installs with --only optional or TTY Install everything. Skill arguments, MCP, ralph-wiggum, and themes are Dropped. They are not LazyPi extras. pi install still works. See Catalog philosophy.
Why does Pi error with “Cannot find module ‘acorn’”?
A catalog package is broken at runtime even though it is present in settings — its dependency footprint is missing on disk (typically a stale checkout under ~/.pi/agent/extensions/ without its node_modules). Run npx @tommy-ca/lazypi update to repair footprints, or reinstall the package. If the error persists, remove the stale checkout directory (for example ~/.pi/agent/extensions/subagent) — Pi loads that package from its npm store instead. Package settings are preserved.
Why do my packages stay on old versions after update?
pi update respects the version pins recorded in settings.json (for example npm:pi-subagents@0.58.0) and does not advance them. To move a package explicitly, reinstall at the version you want: pi install npm:<pkg>@<version> (or omit the @version to track latest). npx @tommy-ca/lazypi status shows the installed pins.
Can I choose what to install?
Yes. On a TTY, the first option is Install everything (the full 17-package catalog) or an interactive picker with core pre-ticked. --yes with no other flags installs the 12 harness-core packages only. Add the optional tier with --only optional or the picker.
Will it overwrite my existing Pi setup?
No. LazyPi reads your existing Pi configuration and skips anything already installed. It's fully idempotent — you can run it as many times as you like without worrying about it clobbering your setup.
Where do the packages come from — are they vetted?
Every package in the LazyPi catalog is hand-picked from the Pi community. They're open source, publicly available on GitHub, and selected for quality and usefulness. LazyPi doesn't publish or maintain them — it just curates and installs them. You can inspect any package by clicking through to its GitHub repo from the catalog.
How do I remove a package I don't want?
Run npx @tommy-ca/lazypi remove to open an interactive picker of installed packages. Or pass the package id directly:

npx @tommy-ca/lazypi remove subagents

Raw pi sources also work: npx @tommy-ca/lazypi remove npm:pi-subagents@0.13.3
How do I keep everything up to date?
Run npx @tommy-ca/lazypi update. This runs Pi's updater to pull in upstream changes for installed Pi packages.
Something's broken — how do I diagnose it?
Run npx @tommy-ca/lazypi doctor. This checks your environment for common problems and reports anything that looks off. It's the first thing to run if Pi isn't behaving as expected after a LazyPi install.
Why is npx/bunx running an old version after a release?
Both runners cache resolved versions: bunx serves from its package cache and npx reuses the extracted copy in ~/.npm/_npx, so a bare npx @tommy-ca/lazypi / bunx @tommy-ca/lazypi can keep serving the previous release until the cache is cleared. Run bun pm cache rm (and/or delete the stale ~/.npm/_npx entry), pin @tommy-ca/lazypi@latest, and check npx @tommy-ca/lazypi --version to see which release is actually running.
Why does npx fail with “lazypi: not found” inside the LazyPi repo?
npm exec matches the spec against the local tree, and the checkout itself is @tommy-ca/lazypi@<version> — so it skips the npx install and tries to run lazypi from ./node_modules/.bin, which never exists for the project's own name. Run npx from any other directory (e.g. ~).
I think a package is missing — how do I suggest it?
If you've found a Pi extension that you think belongs in the catalog, open an issue on GitHub with a link to the package. The membership bar is in Catalog philosophy.
Does it work on Windows, Mac, and Linux?
LazyPi requires Node.js 20+ and works anywhere Pi does — macOS, Linux, and Windows (via WSL or a Node-compatible shell). If you hit a platform-specific issue, run npx @tommy-ca/lazypi doctor first, then open an issue.
