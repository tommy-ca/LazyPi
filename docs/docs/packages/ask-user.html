Ask User

Required structured questions, not hard approval or an authorization boundary.

What it does

ask_user presents one focused, multiple-choice question when the target file, create-vs-edit, acceptance criteria, or a mutually exclusive implementation option is undefined. One avoided rewrite pays for the pause.

It also asks a batch of 2-4 independent questions in one prompt, with a review page before submitting. Use a batch for decisions whose prerequisites are already settled. Anything that depends on another answer belongs in a later call.

Related workflow: when a request is ambiguous, Pi asks before producing a large diff. This is an efficiency feature — a cheap structured question in exchange for not generating the wrong thing.

Settings

Defaults persist in ~/.pi/agent/ask-user.json, or in <agent-dir>/ask-user.json when PI_CODING_AGENT_DIR is set. The file covers display mode, single-select layout, the optional comment row, context expansion, and the overlay and comment shortcut keys.

Per-call tool parameters override environment variables, and environment variables override the settings file. The file is read on every call, so an edit applies without restarting Pi. A file that exists but is not valid JSON fails the call with its path in the error, so a broken configuration is visible instead of silently ignored.

Set emitFullEvents to true only when a trusted extension needs the data. It shares answers, comments, freeform text, and offered options with other installed extensions through lifecycle events, and it is off by default.

Why it's included

Agents that guess on ambiguity generate confident, costly, hard-to-reverse changes. Ask User provides structured clarification. It does not force all tools through human approval. Registration does not establish native loading, unattended denial, child authorization, or readiness.
