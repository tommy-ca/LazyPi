Dynamic Workflows

Intent-driven fan-out workflows over pi-subagents: the /workflows TUI, /deep-research, resume from run IDs, token/cost accounting, and optional git-worktree isolation.

What it does

Dynamic workflows turns one request into a JavaScript orchestration script that fans work out across isolated subagents, routes each task to the right model, cross-checks the results, and returns one synthesized answer. Instead of one agent holding a huge task in a single context window, workflows run concurrent subagent sessions — up to 16 at a time — and keep intermediate work in script variables.

Intent-driven by default: mention workflow or workflows in a message and Pi handles a decomposable request by fanning it out across agents — or run the built-in patterns directly. Runs are resumable from a run ID (resumeFromRunId) with journaled replay, so unchanged agent calls replay from cache instead of re-spending tokens. Real token and cost accounting is reported per run, and parallel agents can edit safely on throwaway branches with isolation: "worktree".

Why it's included

The harness you get from LazyPi is meant to be driven — and its operator runs fan-out workflows daily. This engine sits on top of the cataloged pi-subagents substrate, turning a bare fleet of subagents into a deterministic, resumable, cross-checked choreography for codebase-wide audits, multi-perspective review, and source-checked research.

Commands

CommandWhat it does
/workflows Open the interactive run navigator — browse phases, agents, models, token usage, and cost; pause, stop, restart, or save runs
/deep-research Source-checked web research with citations, run as a fan-out workflow
workflow Runtime tool: Pi invokes it to start a workflow script, manage background runs, or call a saved workflow inline
