Installation

Unpublished registration candidate. Installation is not native readiness.

Prerequisites

  • Node.js 20 or later for the LazyPi CLI
  • npm (bundled with Node.js)

Pi and individual extensions can require a newer runtime. For example, pi-web-access releases declare Node.js 22.19 or later. Check the requirements for the versions you install and the runtime used to launch Pi.

You do not need to install LazyPi globally. npx downloads and runs it on demand.

Run it

npx @tommy-ca/lazypi

That's the entire install command. LazyPi will:

  1. Show an interactive picker: Install everything or select individual packages
  2. Check whether Pi is installed after you confirm a nonempty selection
  3. Offer to install Pi if it's missing
  4. Register your selection without certifying native loading or readiness

Install everything vs. interactive picker

Choosing Install everything on a TTY installs all 6 core registrations, including Web Access. --yes with no other flags and --only core select the same six. The picker preselects all six. The optional category is empty. --only optional selects nothing and skips Pi setup without changing settings; --except optional selects all six.

The interactive picker lets you browse the catalog and select only what you want. Use arrow keys to navigate, space to toggle, and enter to confirm.

LazyPi completes package selection before Pi setup. Cancelling either selection prompt or confirming an empty picker installs nothing and leaves settings, model overrides, and backups unchanged. An empty --except result also skips Pi setup. Invalid settings still stop installation before setup.

Registration limits

Fresh PStack installs use git:github.com/tommy-ca/pstack@f1571b8431034dcd195f4ea055ccf1c84fc14fc8. Existing canonical pins stay installed without upgrade or duplication. Support packages retain ordinary npm semantics. npm:@zenspc/pi-pstack is not an alias.

Sandbox is disabled until explicitly configured. Ask User is not hard approval. Registration does not prove loading, canonical role binding, tool restrictions, child authorization, or recovery. Untrusted or unattended work requires a container or VM. Offline checks do not satisfy operator promotion.

Retired IDs reject in --only and --except. Curation retirement does not remove, disable, or freeze installed packages. Exact sources remain Other, and broad updates still apply. Use exact installed sources for removal because retired IDs no longer resolve catalog or legacy mappings.

Idempotency

LazyPi skips installed packages. Selecting subagents also sets model: "" for context-builder, planner, researcher, reviewer, scout, and worker, even when the package is already installed. They inherit the session model when no higher-precedence model override applies. Other override keys remain unchanged. A re-run is a no-op when the selected packages and these overrides are already present.

No global LazyPi installation is required. Runner caches can persist and may serve an older release. See the FAQ for cache troubleshooting. Installed Pi packages, settings overrides, and timestamped settings backups also persist.

Before LazyPi changes an existing settings file, it saves a sibling backup named settings.json.lazypi.<timestamp>.bak. Package removal does not delete these backups or runner caches.

After installation, head to First Steps to launch Pi, authenticate, and try a few commands that show what changed.
