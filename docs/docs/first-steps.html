First steps

Separate package registration from effective loading and security.

This checkout is an unpublished candidate. TTY Install everything is 6 packages. The default and picker preselection are all six core registrations, including Web Access. The optional category is empty. --only optional skips setup and changes nothing.

Inspect registered sources

npx @tommy-ca/lazypi status

Status reads settings, not loaded tools. Older canonical PStack pins are preserved. Retired registrations appear as Other. See retirement limits and capability losses.

Check configuration before execution

PStack registration does not bind canonical roles or establish native integration. Sandbox is disabled until explicitly configured. Ask User presents questions, not hard approval. Verdict's exemptions and manual shell escapes are not classified. Use a container or VM for untrusted or unattended work.

Authentication is separate from installation. In an appropriately authorized environment, Pi's /login configures a provider. Do not interpret registration or offline tests as authorization to execute extensions.

Inspect subagent models

Selecting Subagents resets six builtin model overrides even on an already-installed run. Other override keys remain. Subagent settings lists the names and backup behavior. Canonical role/model semantics remain unverified.

Manage installed registrations

npx @tommy-ca/lazypi remove
npx @tommy-ca/lazypi update

Removal lists installed catalog entries. Use exact installed sources for retired registrations because their IDs and legacy mappings no longer resolve. Update remains broad and can update unmanaged installed packages while respecting pins. Neither curation retirement nor package removal cleans runner caches, model overrides, or backups.

Native loading, dispatch, independent child authorization, headless denial, exit/recovery, and operator promotion still need separate evidence. No readiness claim follows from these steps.
